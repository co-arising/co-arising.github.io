实战 · 从零到完整闭环

指南：把整件事跑起来

三个层级：L1 是只需 Node 的 Counter 教程，L2 区分银行生成路径与正式工作坊前置条件，L3 通过 MCP 查询图谱。本地生成命令不等于正式服务验收。下文分别说明银行的新技术通过与仍未签收的独立体验。

环境——先选范围

Node-only 教程与银行 source 范围需要 Node ≥ 22.13.0（node:sqlite）F-13。编译生成的 Scala 需要 JVM 与 sbt。正式 anchors/code/service 验收还需要显式配对材料；正式 code/service 范围限于原生 Darwin x64 / JDK11 F-28。将命令视为验收入口前，先读前置条件。

路径 A · 原生 Node

# macOS (Homebrew)
brew install node@22

# 或用 nvm
nvm install 22
node --version   # 必须输出 v22.13.0 或更新

路径 B · Docker 用于 Node-only 工作

docker run --rm -it -v "$PWD":/work -w /work node:22 bash

这个容器是 Node 工作的一种选择，不能代替银行 code/service 已验收的原生环境。

便捷 Scala 编译 · JVM + sbt

# macOS
brew install openjdk@11 sbt

# 或 JVM 工作的 Docker 变体
docker run --rm -it -v "$PWD":/work -w /work sbtscala/scala-sbt:eclipse-temurin-11.0.24_9_1.10.11_2.13.14 bash

L1 · Counter 教程——完整闭环的缩影

一个聚合、一个切片、一条规则。你将编写、生成、双向查询锚点、验证、改树、看到过期、再生成。绿灯由工具打印——信它，别信你的眼睛。

创建项目

拒绝碰已存在的目录

node ../metarch-truthsrc/bin/truthsrc.js init counter-lab --format human 然后 cd counter-lab。看看里面：truth/example/… 就是整棵作者树——aggregate.yaml（状态 + @rule）和一个切片。

先看计划再落盘

此时什么都没写

… generate-project --plan --format human——计划列出它将要写的每个文件。读它。生成永远不该是惊喜。

生成 & 查看新鲜度

绿灯：inputs=current · evidence=verified · synchronized=true

… generate-project --format human 然后 … status-project --out . --format human。打开一个生成文件——每个都带着锚点头。

双向追问

闭环合上的那一刻

… query-project --knowledge SetCount → 精确的文件和区间。然后 … query-project --file <那个文件> --symbol <符号> → 回到那条规则。知识与代码，接通了。

改真源，不改代码

看到过期，然后重新同步

编辑 truth/…/aggregate.yaml：把 count 默认值 0 改成 2。status-project 现在报告 changed。… generate-project --update --plan 展示 diff 计划；--update 应用它。再跑一次 generate——写入：0。幂等就是闸门。

验证 & 拍张快照

绿灯：verify passed

… verify-project --out . 对照文件字节重新证明每个锚点。… view-project --out . --html counter-map.html 导出单文件地图——离线也能打开。

L2 · 银行生成与正式工作坊范围

前置条件——不是安装捷径

Node-only 真源检查、便捷生成与正式工作坊验收是不同入口。便捷 npm run project 可取得引擎，但正式 anchors/code/service 同时要求显式 clean1134 归档和已准备的 runtime-supply 目录。配套 CLI、完整配对源码材料及归档尚无确认的公开交付渠道（DEF-15）。不要把本页当成一条命令即可公开复演的承诺。

正式范围必需输入与环境
source自己的银行 checkout、完整相邻配套工具 checkout 与 Node。不需要 JVM、数据库或浏览器。拒绝无用的 --archive 和 --runtime-supply 参数。
anchorssource 输入，加上--archive：已有 clean1134 归档的绝对路径（固定编译器/工具链与第三方依赖），以及--runtime-supply：已有且已准备的 0.3.0 receipt.json + maven/ 目录绝对路径，与项目匹配 F-23。两者缺一不可。
code上述两份供给，加上原生 Darwin x64、由 --java-home 显式选择的已安装 x64 JDK11，以及 sandbox/Python 前置 F-28。
servicecode 全部前置，再加新的独占资源租约、可用 Docker/socket 与固定数据库镜像，以及显式 Playwright module 和 chrome-headless-shell 路径。service 不能省略浏览器。

正式验收不会隐式下载、prepare 或回退 P23。组合供给时排除归档中的旧引擎，选择独立锁定的 runtime supply；不重签原归档。旧离线包迁移仍单列（DEF-20）。详见已验范围与材料契约。

仅前置检查——先设置自己的真实路径

在自己的银行 checkout 根目录运行，并已取得相邻配套工具 checkout。将 BANK 设置为该 checkout 的绝对路径。code 范围还需将 ARCHIVE、RUNTIME_SUPPLY 与 JAVA_HOME_BANK 设置为上述已存在的本地绝对路径。这些是必填变量，不是下载地址或随页提供的文件。

source 前置检查不带 archive/runtime 参数。

: "${BANK:?Set BANK to your own bank checkout absolute path}"
node "$BANK/tools/bank-workshop.mjs" doctor --through source --format human

code 前置检查显式选择两份供给与已安装的 JDK。

: "${BANK:?Set BANK to your own bank checkout absolute path}"
: "${ARCHIVE:?Set ARCHIVE to the existing clean1134 archive absolute path}"
: "${RUNTIME_SUPPLY:?Set RUNTIME_SUPPLY to the prepared 0.3.0 supply directory absolute path}"
: "${JAVA_HOME_BANK:?Set JAVA_HOME_BANK to the installed x64 JDK11 absolute path}"
node "$BANK/tools/bank-workshop.mjs" doctor --through code \
  --archive "$ARCHIVE" --runtime-supply "$RUNTIME_SUPPLY" \
  --java-home "$JAVA_HOME_BANK" --format human

Doctor 是前置检查，不是验收。后续 verify 必须在银行 target/ 下从未使用的直接子目录创建新 run，父目录须已存在，路径须为规范绝对路径。不得复用旧 run。不带 --run 的 doctor 不检查该父目录。report/view 与独立 session start/status/stop 使用 run 的封存供给；session 拒绝 archive/runtime-supply override。后续修补需要新执行证据，不能给旧报告改标签。

便捷生成——不是工作坊验收配方

已有本地路径验证真源、生成至 generated/current/，将手写生产源码与生成项目一起编译，并验证锚点。首次生成可从 Maven Central 下载 SHA-256 钉定的引擎；这不证明上述正式供给已齐备，也不启动或签收服务。

git clone https://github.com/MadPolaris/bank-wealth-demo.git
cd bank-wealth-demo
npm run validate
npm run compile
node ../metarch-truthsrc/bin/truthsrc.js graph --tree truth/bank-wealth --out bank.graph.sqlite
npm run project
cd generated/current && sbt compile
sbt test
cd ../.. && node ../metarch-truthsrc/bin/truthsrc.js verify-project \
  --project truthsrc.project.json --out generated/current

历史采集，2026-11-11：0 硬发现、157 个原子往返逐字节一致 F-01 F-02；235 个生成文件 F-04；534 个源文件、0 编译错误 F-06；23/23 项生成单元测试，不是独立手写测试 F-07；792 个锚点通过验证 F-05。不声称新服务候选仍有这些相同计数。

当前技术证据，不是你的 run 的结果

bank030-relocated-20261112-02 在 2026-11-12 的 source / anchors / code / service 均通过并复核 F-24，包括真实数据库/HTTP 与自动浏览器观测 F-26。旧 P23/service02 失败仍是历史事实（DEF-06）。独立体验仍未签收：session03 未达 readiness，清理不是通过，后续修补候选未执行（DEF-07）。公开材料（DEF-15）与真人验收（DEF-16）不由该技术结果代签。详见银行分层结果与剩余边界。

L3 · 把图谱接进 Claude Code（MCP）

这是智能体化的回报：一个靠查询知识图谱而不是 grep 仓库来规划变更的智能体。MCP 服务器自带 26 个只读工具 已验证。

注册服务器

# 在任意目录执行（路径指向你的 metarch-truthsrc 检出）
claude mcp add truthsrc -- node /absolute/path/to/metarch-truthsrc/bin/truthsrc.js mcp

安装查询技能

工具链自带一个技能，教智能体查询纪律（预算化的图谱行走、跟随 next_actions、blast_radius 的宁多报不漏报语义）。把它拷进你的项目：

mkdir -p .claude/skills
cp -r /absolute/path/to/metarch-truthsrc/skills/truthsrc .claude/skills/

练习：按影响半径规划一次增量变更

给智能体一个需求

在 Claude Code 里，位于 bank-wealth-demo

试试：「我们需要改变定投扣款失败时的行为。在提出任何方案之前，先查询真源图谱中 SipInstallmentFailed 的影响半径，并报告受影响的切片、读模型和流水线。」

看纪律起作用

describe → expand → blast_radius，跟随 next_actions

智能体应当沿传导边从事件出发，列出受影响的守卫/读模型/流水线（3 跳内数十个节点），然后才对着树起草变更提案——而不是对着代码。

套用编辑契约

智能体起草；闸门裁决

任何树的编辑都必须以 validate（0 硬发现）和 roundtrip（逐字节一致）全绿收尾，然后 generate-project --update --plan 在应用前看清再生成 diff。这就是守护纪律，机械化执行。

还附带：从既有代码库抽取树、从可达数据抽取树、或从一句话描述引导工作坊草稿的技能——见工具链仓库的 skills/。

05

红线与恢复

绝不

绝不手工编辑派生产物——编译后的 canonical、.truthsrc/、台账、锚点、生成文件。它们会被再生成；你的编辑会作废（而且会被发现）。如果生成代码看起来不对，修的地方在树里——这正是全部意义所在。  ·  绝不强行闯过红闸门。validate 的发现和 roundtrip 的发散是信息，不是障碍。  ·  图谱存储？随便删——它是纯缓存，一条 graph 命令重建。

卡住了？工具链 README 有诊断章节；事实页精确告诉你哪些声明在哪一天被验证——如果你的数字和我们的不一样，信你的终端。
