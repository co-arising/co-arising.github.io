实战 · 从零到完整闭环

指南：把整件事跑起来

三个层级，每一层末尾都有一盏绿灯：L1 Counter 教程（只要 Node，约 10 分钟），L2 银行示例流水线（加一个 JVM，约 30 分钟），L3 把 MCP 服务器接入 Claude Code，让智能体靠查询图谱来规划一次增量变更。任何一步失败，最后一节会告诉你红线在哪。

00

环境——两条路任选，都是一等公民

工具链需要 Node ≥ 22.13.0（原因正是内置的 node:sqlite）。Level 2 另外需要 JVM（11+）和 sbt。下面每条命令都可以直接复制粘贴。

路径 A · 原生 Node

# macOS (Homebrew)
brew install node@22

# 或用 nvm
nvm install 22
node --version   # 必须输出 v22.13.0 或更新

路径 B · Docker（不想动宿主机 Node 的话）

docker run --rm -it -v "$PWD":/work -w /work node:22 bash
# 现在你在容器里的 Node 22 上；下面的一切原样可用

仅 Level 2 需要 · JVM + sbt

# macOS
brew install openjdk@11 sbt

# 或 JVM 工作的 Docker 变体
docker run --rm -it -v "$PWD":/work -w /work sbtscala/scala-sbt:eclipse-temurin-11.0.24_9_1.10.11_2.13.14 bash
01

拿到工具链

npm 发布在台账上（DEF-03）——在那之前，源码检出就是正统的安装方式。零 npm 运行时依赖意味着检出即整个工具链。

git clone https://github.com/co-arising/metarch-truthsrc.git
npm install --prefix metarch-truthsrc        # 只有开发依赖；运行时只用标准库

# 冒烟测试——不碰 SQLite，无副作用
node metarch-truthsrc/bin/truthsrc.js --help

提示：alias truthsrc="node $PWD/metarch-truthsrc/bin/truthsrc.js" 能让本页后面读起来更顺。

02

L1 · Counter 教程——完整闭环的缩影

一个聚合、一个切片、一条规则。你将编写、生成、双向查询锚点、验证、改树、看到过期、再生成。绿灯由工具打印——信它，别信你的眼睛。

创建项目

拒绝碰已存在的目录

node ../metarch-truthsrc/bin/truthsrc.js init counter-lab --format human 然后 cd counter-lab。看看里面：truth/example/… 就是整棵作者树——aggregate.yaml（状态 + @rule）和一个切片。

先看计划再落盘

此时什么都没写

… generate-project --plan --format human——计划列出它将要写的每个文件。读它。生成永远不该是惊喜。

生成 & 查看新鲜度

绿灯：inputs=current · evidence=verified · synchronized=true

… generate-project --format human 然后 … status-project --out . --format human。打开一个生成文件——每个都带着锚点头。

双向追问

闭环合上的那一刻

… query-project --knowledge SetCount → 精确的文件和区间。然后 … query-project --file <那个文件> --symbol <符号> → 回到那条规则。知识与代码，接通了。

改真源，不改代码

看到过期，然后重新同步

编辑 truth/…/aggregate.yaml：把 count 默认值 0 改成 2。status-project 现在报告 changed。… generate-project --update --plan 展示 diff 计划；--update 应用它。再跑一次 generate——写入：0。幂等就是闸门。

验证 & 拍张快照

绿灯：verify passed

… verify-project --out . 对照文件字节重新证明每个锚点。… view-project --out . --html counter-map.html 导出单文件地图——离线也能打开。

03

L2 · 全规模的银行示例

157 个原子、3 个聚合、2 个 saga、4 条流水线——同样的六道闸门，工业级体量。从这里开始，绿灯就是项目自己的验收层。

git clone https://github.com/MadPolaris/bank-wealth-demo.git
cd bank-wealth-demo

# 闸门 1+2 —— validate & roundtrip（一条命令；roundtrip 是闸门的一部分）
npm run validate            # ✅ 0 硬发现 · roundtrip：157 原子逐字节一致

# 闸门 3 —— 编译并构建图谱存储（389 节点 / 413 边）
npm run compile
node ../metarch-truthsrc/bin/truthsrc.js graph --tree truth/bank-wealth --out bank.graph.sqlite

# 闸门 4 —— 生成 CQRS 项目（235 个文件）
npm run project             # 写出 generated/current/

# 闸门 5 —— 手写区在仓库里已经是完整的（35 个文件）；
#          它作为生成构建的一部分一起编译：
cd generated/current && sbt compile   # ✅ 0 错误，534 个源文件
sbt test                             # ✅ 23/23

# 闸门 6 —— 证明每个锚点（792 个）
cd ../.. && node ../metarch-truthsrc/bin/truthsrc.js verify-project \
  --project truthsrc.project.json --out generated/current
你刚刚证明了什么

一份 157 原子的银行财富领域描述可以编译、变成可查询的图谱、生成可编译且通过测试的 Scala 代码库、其 792 个锚点对照文件字节验证通过——而且每一步你都能重跑。你没有跨过的边界：端到端跑起 HTTP 服务（台账 DEF-06 DEF-07）。

04

L3 · 把图谱接进 Claude Code（MCP）

这是智能体化的回报：一个靠查询知识图谱而不是 grep 仓库来规划变更的智能体。MCP 服务器自带 26 个只读工具 已验证。

注册服务器

# 在任意目录执行（路径指向你的 metarch-truthsrc 检出）
claude mcp add truthsrc -- node /absolute/path/to/metarch-truthsrc/bin/truthsrc.js mcp

安装查询技能

工具链自带一个技能，教智能体查询纪律（预算化的图谱行走、跟随 next_actions、blast_radius 的宁多报不漏报语义）。把它拷进你的项目：

mkdir -p .claude/skills
cp -r /absolute/path/to/metarch-truthsrc/skills/truthsrc .claude/skills/

练习：按影响半径规划一次增量变更

给智能体一个需求

在 Claude Code 里，位于 bank-wealth-demo

试试：「我们需要改变定投扣款失败时的行为。在提出任何方案之前，先查询真源图谱中 SipInstallmentFailed 的影响半径，并报告受影响的切片、读模型和流水线。」

看纪律起作用

describe → expand → blast_radius，跟随 next_actions

智能体应当沿传导边从事件出发，列出受影响的守卫/读模型/流水线（3 跳内数十个节点），然后才对着树起草变更提案——而不是对着代码。

套用编辑契约

智能体起草；闸门裁决

任何树的编辑都必须以 validate（0 硬发现）和 roundtrip（逐字节一致）全绿收尾，然后 generate-project --update --plan 在应用前看清再生成 diff。这就是守护纪律，机械化执行。

还附带：从既有代码库抽取树、从可达数据抽取树、或从一句话描述引导工作坊草稿的技能——见工具链仓库的 skills/。

05

红线与恢复

绝不

绝不手工编辑派生产物——编译后的 canonical、.truthsrc/、台账、锚点、生成文件。它们会被再生成；你的编辑会作废（而且会被发现）。如果生成代码看起来不对，修的地方在树里——这正是全部意义所在。  ·  绝不强行闯过红闸门。validate 的发现和 roundtrip 的发散是信息，不是障碍。  ·  图谱存储？随便删——它是纯缓存，一条 graph 命令重建。

卡住了？工具链 README 有诊断章节；事实页精确告诉你哪些声明在哪一天被验证——如果你的数字和我们的不一样，信你的终端。
