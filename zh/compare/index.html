保留能帮助团队发现、描述和运行领域的工具。当你还需要把已声明行为与生成实现可审阅地连起来、再追溯回去时，可以考虑真源工作流。这是一项具体职责，不是替换所有建模或数据平台。

01

先问清要完成什么工作

下表提供互补的起点，不是完整的厂商能力审计。不因为某个工具所属的类别，就推断它缺少某项功能或集成。

你的任务可以从哪里开始真源如何配合需要核对的边界
发现共同的业务语言EventStorming / Domain Storytelling保留讨论与例子，将决策整理成可审阅草稿，再明确已接受的规则与关系。文件格式不会取代工作坊方法；从草稿晋升仍是人的决策。
协作建立模型Qlerify 等建模画布用画布支持讨论；把导入视为权威之前，先逐项审阅导出字段如何映射到声明。本站路线尚未交付画布双向集成，延期项见 DEF-02；不宣称整个产品的覆盖率分数。
发布架构目录EventCatalog目录帮助人浏览领域、服务与事件；真源工作流补充自己的已声明行为生成与来源锚点检查。职责互补不等于已有自动目录导出器或同步契约。
探索限界上下文与上下文映射ContextMapper用战略建模讨论边界；本项目把受支持声明连接到图谱与 CQRS/ES 实现。CML 投影是方向，不是已交付适配器，也不据此断言 ContextMapper 的能力上限。
实现事件溯源应用prooph / Event Engine为应用选择合适的语言与运行时。这里已展示的生成目标是 Scala CQRS/ES，Saga 与 Monarch 各有协调职责。知识层不会让不同运行时端口自动互换；这里未展示 PHP 生成目标。
连接企业数据与动作Palantir Ontology 等语义平台语义模型与真源模型都能表达关系和行为；本项目侧重作者文件、生成源码与可检查的来源记录。按实际需求评估平台集成与治理；这里不做兼容性、功能对等或退出厂商平台的评估。
02

标准已经存在，实现状态要另说

提出合理的标准映射，不等于已经交付并测试了导出器。下方把当前接口与拟议衍生物明确分开。

当前接口

SQLite 知识图谱

本地图谱表示支持真实查询。Explorer 读取随站点提供的银行快照 F-03，不是你的仓库的实时视图。

当前接口

MCP 访问

工具链经 stdio JSON-RPC 提供面向读取的工具 F-16。这是查询接口，不是下方所有标准的导出能力。

拟议衍生物 · 不是已交付集成
任务标准或格式拟议映射本项目状态
验收例子Gherkin场景与已声明行为 → Given / When / Then feature已设计，未构建 DEF-01。预期行为仍需独立审阅。
事件契约AsyncAPI事件与载荷 schema → 消息、通道和操作拟议投影，不是当前导出能力。
事件信封CloudEvents事件元数据 → 可互操作信封拟议映射，不宣称已符合标准。
HTTP 契约OpenAPI命令与查询 → 操作和 schema拟议投影，不在此宣称已有导出器。
架构视图C4 / Structurizr DSL显式架构声明 → 系统与容器视图拟议投影；仅有领域关系不足以指定部署拓扑。
服务目录Backstage catalog上下文与已声明依赖 → 目录实体拟议投影，不是同步集成。
DDD 建模ContextMapper CML限界上下文与上下文映射 → CML 声明拟议投影，不是双向适配器。
采用时不扩大承诺

先从已有接口开始。新增投影之前，先约定身份、语义、信息损失与所有权，再实现导出器。不要让衍生物不知不觉变成另一份可编辑真源。
