观看原演讲视频 ↗

解决问题
公开研究显示模糊提示会使 LLM 编码准确率暴跌 20%–40%、上线回归翻倍；看似通顺的自然语言需求文档中往往隐藏着跨句矛盾（如同时允许与禁止缺货预订）或状态缺口（未定义闲置订单处理）。
核心理论
神经符号前置校验三步法（“LLM 翻译、求解器验证、人类拍板”）：将单句/多句 Spec 采样翻译 7–10 次为 SMT-LIB 数学公式，用 SAT/SMT 求解器按逻辑等价性聚类不同解释，精准定位句内歧义、跨句冲突与规则盲区，交由掌握隐性领域知识的人类二选一裁决。
验证成果
落地为 AWS Kiro Specification Analyzer，在编码 Agent 动手之前即可机械化阻断逻辑矛盾与规范漏洞，避免将需求歧义放大成代码库技术债。
工具与栈
AWS Kiro Specification Analyzer、SMT-LIB 形式化表达、SAT/SMT 求解器、多采样逻辑等价聚类管线。
#03 S · 9.6

Sub-Agents Are a Distributed System (And Nobody Gave You a Consistency Model)

Gish · Microsoft (Principal Software Engineer, 个人观点)

观看原演讲视频 ↗

直指多智能体编排的理论盲区：子智能体本质就是分布式系统，却缺失一致性模型。系统提出 SAFE 交接一致性模型，将拜占庭故障、脏读、幂等、栅栏令牌与 Saga 补偿引入 Agent 架构。

解决问题
多子智能体并发读写共享上下文并调用外部工具时，频繁出现半成品装成功（类拜占庭故障）、一个 Agent 的猜测被其他 Agent 当事实放大（脏读）、超时重试触发重复副作用、无界并发压垮下游等经典分布式故障。
核心理论
提出 SAFE 一致性模型：Source Reads（所有事实带来源版本与时效戳，区分观测与推断防脏读）、At-Most-Once Effects（副作用带唯一 ID、一次性栅栏令牌 Fencing Token 审批与回读确认，参考 Kleppmann 与 1987 Sagas 补偿）、Fan-out Budgets（下游限流门禁与有界等待）、Explicit Outcomes（在编排器代码中强制把结果类型化为 partial/stale/unknown，把 Agent 输出当不可信外部输入重新验算）。
验证成果
在开源项目 MCP Pacemaker 监督桥接器中完整落地，根治了冷启动并发锁冲突、超时掩盖崩溃退出码及状态恢复误删会话等线上 Bug，并形成互联网草案规范。
工具与栈
MCP Pacemaker（开源监督桥接器）、A2A / MCP 协议显式状态槽、分布式系统经典理论（Lamport 1978 / FLP 1985 / Sagas 1987 / Fencing Tokens）。

核心理论
人类退出循环的每一处都必须由“模型、Harness 或环境”接管；CLAUDE.md 只保留代码中看不出的隐性上下文；不可逆风险用确定性 Deny 规则与 OS 沙盒/云端隔离兜底（Auto Mode 拦截 89% 危险命令远超人类的 14%，但仍有 11% 漏网）；用 exit 2 Hooks 强制验证闭环；由强规划模型（Fable）做总控编排、强执行模型（Opus 5.5）跑子线程。
验证成果

工具与栈
Claude Code（Opus 5.5 + Fable 5.2）、Auto Mode 分类器、doctor prompt audit、OS 级 Sandbox 与 Cloud Sessions（Network Secrets）、exit 2 Hooks、Claude Code Projects（Beta）。
#05 S · 9.5

An Agent's Change Is Not Safe Until Its Recovery Has Been Tested

Tan & Dolly · UndoBench / EvoUndo 研究团队

观看原演讲视频 ↗

发布 UndoBench 与 EvoUndo 两项重磅研究：实测证明 Agent 正常成功率 84% 但故障恢复率仅 47%、42% 的正向自演进变更无法安全回滚；提出“变更前状态见证 + 独立恢复验证器”将可恢复率拉升至 92%。

解决问题
Git revert 无法撤销外部 API 调用、数据库写入及 Agent 对自身 Harness（工具/中间件/配置）的修改；超时重试会导致 54% 的重复副作用，单纯靠 Prompt 喊“请修好回滚”修复率为 0%。
核心理论
将“可恢复性”前置为变更准入条件（Admission Gate）：变更前捕获精确状态见证（Pre-State Witness），声明效果契约与恢复计划，在测试环境实测“变更→回滚→独立验证器核验恢复一致”全通后才允许准入；按故障阶段差异化处理（未变更重试 / 有见证恢复 / 已提交则执行 Saga 补偿 / 无法验证则升级人工）。
验证成果
UndoBench（2,880 对实验）暴露 47% 恢复率与 54% 重复副作用；EvoUndo（600 项自演进任务）中扩展恢复原语与状态见证后，197 个原本 0% 可修复的缺陷成功恢复 180 个（92%），有效准入改进率净增 30 个百分点。
工具与栈
UndoBench、EvoUndo（开源 GitHub 算法与验证框架）、Pre-State Witness 与独立 Recovery Verifier。
#06 S · 9.4

Jarred Sumner · Anthropic (Bun 创始人)

观看原演讲视频 ↗

揭秘如何用 Claude Code 在一个月内 5 次重写并合并数百万行 Bun AOT 编译器，强调“选可验证的项目”：只有独立于实现且早于项目存在的测试预言机（Oracle）才能让百万行 AI 代码值得信任。

解决问题
如何自信地合并由 Agent 编写的数百万行底层系统代码，同时避免 Agent 修改/污染测试套件或写出“表面通过但充斥垃圾逻辑”的实现。
