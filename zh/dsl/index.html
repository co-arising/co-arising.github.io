一门给真源树的描述语言

一棵 YAML 树是唯一的编辑界面：工作坊笔记经 inbox 流入，形式化原子持有编译后的契约，一张 22 种带类型关系的注册表就是元模型。本页发布语言的战略层（上下文、子域、地图）与范围层（种类、关系、闸门）。可视化编辑工具在台账上。

第零规则

作者树是唯一的编辑界面。下游的一切——编译后的 canonical、知识图谱、生成的代码、台账、锚点——都是派生物，都会被重新生成。手工编辑派生物，按契约作废。这一条规则，是其他一切保证成为可能的原因。

02

范围层：你能说什么

两套词汇表，一张注册表。工作坊笔记类型是发现面（一墙便签的去处）；原子种类是编译后的契约。已对照 lib/shared.mjs 验证

15 种笔记类型——工作坊入口

分组类型承载什么
行为event · command · policy · timer领域事件、请求变更的命令、反应策略、时间触发器——EventStorming 的词汇。
结构aggregate · entity · field · readModel一致性边界、实体、带血缘的字段、读侧投影。
战略context · subdomain · relation限界上下文、核心/支撑/通用分类、上下文间关系——DDD 的战略层。
人与系统role · externalSystem角色（及其可发出的命令，R12）和边界上的外部系统。
知识question · story不许悄悄消失的开放问题 / 热点，以及等待安放的用户故事。

04

一个真实切片，原样未剪

来自 truth/bank-wealth/…/credit-balance/slices/initialize-account.slice.yaml。这是这门语言最密的样子：一条命令、五个守卫、一个事件、折叠、溯源。

kind: slice
aggregate: CreditBalance
command: InitializeAccount
payload:
  {
    "name": "InitializeAccount",
    "parameters": [
      "resource: AccountId @BUSINESS_INPUT",
      "currency: String @BUSINESS_INPUT",
      "amount: Money @BUSINESS_INPUT"
    ],
    "guards": [
      "@guard[invariantRef](reject ACCOUNT_ID/ACCOUNT_ID: \"param.resource == state.id\")",
      "@guard[invariantRef](reject ACCOUNT_CURRENCY/ACCOUNT_CURRENCY: \"param.currency == \\\"CNY\\\" …\")",
      "@guard[invariantRef](reject ACCOUNT_INIT_ONCE/ACCOUNT_INIT_ONCE: \"!state.initialized\")",
      "@guard[invariantRef](reject ACCOUNT_SEED_NONNEGATIVE/ACCOUNT_SEED_NONNEGATIVE: \"param.amount.amount >= 0.00\")"
    ],
    "produces": [ "AccountInitialized" ],
    "provenance": { "author": "agent-assisted-bank-v1", "approvedBy": "user-approved-p24-p25-bank-joint", … }
  }
events:
  {
    "AccountInitialized": {
      "payloads":  [ "resource: AccountId @PROPAGATED", "amount: Money @PROPAGAGED", … ],
      "bindings":  [ "resource <- param.resource", "amount <- param.amount", … ],
      "foldAssignments": [
        "initialized := \"literal:true\"",
        "accountBalance := @fold[put](key=event.currency, value=event.amount)"
      ]
    }
  }
守卫

有牙齿的规则

每条守卫引用一条具名不变量（ACCOUNT_SEED_NONNEGATIVE）和一个用于拒绝的错误码。「余额非负」不再是一条注释——它编译进生成的命令处理器。

绑定

载荷从哪里来

每个事件字段要么从参数传播而来，要么是计算出来的——字段级的溯源，这正是读模型血缘（R10/R11）建立其上的东西。

折叠

历史变成状态

foldAssignments 定义事件如何更新聚合状态——生成的 event applier 实现的就是这套代数。

05

治理：三道闸门，不是风格指南

validate——0 个硬发现

对作者树做结构 + 语义验证

未知种类、悬空引用、事件在两处定义、切片没有所属聚合——全是硬发现。零是唯一可接受的计数。银行树截至 2026-11-11：0 硬发现 已验证。

roundtrip——逐字节一致

树 → canonical → 树，必须精确复现作者文件

这是反格式漂移闸门。如果编译「顺手规范化」了任何东西，往返就会发散、闸门就会失败。银行树：157 个原子，逐字节一致 已验证。

compile-products——严格契约

形式产物必须先满足自己的 schema 才能被使用

端口、saga IR、执行 IR：从树编译而来的带类型、带版本的产物，各有各的验证。生成代码只消费冻结后的产物。

智能体

给 AI 智能体的编辑契约就是这三道闸门再加守护规则：每一批编辑以 validate 与 roundtrip 全绿收尾；payload 文本逐字保留；树内不许出现工具痕迹；一个事件只在一个切片中定义。它随工具链发布为 AGENTS.md 和一个查询技能包。

06

今天与明天的编辑体验

今天的编辑界面是 YAML 文件加三个抽取技能（从代码库、从可达数据、从一句话描述）。可视化编辑——从 Qlerify 或 Miro 导入工作坊画板、从既有仓库逆向抽取一棵树——已为它留好设计但尚未构建：DEF-02。
