生命周期

真源树 → 代码，再回来

六个阶段，每段一条精确命令、一道绿/红闸门。闭环闭合两次：一次向前（树 → 图谱 → 代码），一次向后（代码 → 锚点 → 树）。以下阶段数字保留银行示例 2026-11-11 的采集日期；更新的技术验收单独陈述，不给旧计数换日期。

01

六个阶段

01 · 编写编辑树

只写 YAML 原子。智能体起草，人类批准——每个原子记录 approvedBy。

02 · 闸门验证 + 往返

validate 0 硬发现；roundtrip 逐字节一致。157 原子 ✓

03 · 图谱编译 & 推送

canonical 投影 → SQLite 图谱：389 节点 / 413 边。

04 · 生成CQRS 代码库

generate-project：235 个文件，0 编译错误。

05 · 手写填手写区

端口与已声明的守卫、fold 由生成器实现；剩余计算和集成进入物理隔离的手写模块——35 个文件，完整实现。

06 · 验证证明血缘

verify-project：792 个锚点；生成单元测试 23/23。

输入过期与输出字节变化是两回事：status-project 分别报告输入和已有生成文件的状态；generate-project --update --plan 给出将要执行的更新动作，不是文本 diff。反查行号要从匹配源码的 UTF-8 span 换算，不猜固定文件/行号。

02

锚点：别人都没交付的那部分

代码生成很常见。出身证明不常见。每个生成文件都携带锚点元数据，把它绑定到产生它的知识节点——而且这个绑定靠重读字节来验证，不是靠信任一份清单。

在自己的 Counter 项目中；具体反查步骤见指南
node "$TRUTHSRC_CLI" generate-project --project truthsrc.project.json --out generated --plan --format human
node "$TRUTHSRC_CLI" generate-project --project truthsrc.project.json --out generated --format human
node "$TRUTHSRC_CLI" query-project --project truthsrc.project.json --out generated --knowledge SetCount --format human
node "$TRUTHSRC_CLI" verify-project --project truthsrc.project.json --out generated --format human
为什么重要

「这一行从哪来的？」

是合规问题、是调试问题，也是新人上手问题——用查询回答，不用考古。

为什么诚实

字节级精度，不是感觉

锚点记录区间；验证重读文件。如果有人改了生成代码，验证会报告漂移，而不是默默继续信任。

为什么智能体需要它

不用 grep 的上下文包

同一张锚点图能为手写智能体打包出精确的上游类型、调用方契约与验收场景——为 AI 协作者闭环。

外部效果与剩余集成

对 mock TA 的效果执行、JDBC 装配、恢复循环、读侧追赶、HTTP 页面——35 个文件，完整实现 已验证，经 unmanagedSourceDirectories 挂进构建。没有任何 BEGIN MANUAL 标记——边界就是文件系统本身。

测试范围

树变了，生成文件被刷新；手写区不被覆盖。2026-11-11 的 23/23 是生成单元测试 F-07：手写生产源码随构建编译，不代表独立手写测试预期已验证。新技术候选的 actor 64 项、readside 47 项通过，保留固定业务预期；两组共享 23 项生成测试，不能相加当作互不重复用例 F-25。

04

saga 与 Monarch 在哪登场

两个引擎，两种职责——用真源声明，绝不混淆：

saga-core · TCC 事务

跨聚合一致性

一个 saga 原子声明参与者（聚合）、阶段（Try / Confirm / Cancel）和补偿。它编译成 saga IR 交给 saga-core——一个 Akka Typed、事件溯源的 TCC 协调器。银行树声明了 2 个 saga：现金付款（投资人出金 → 归集入金 → 订单确认）和独立退款。

monarch-core · 阶段队列

流程编排

一个 pipeline 原子是有序的业务步骤队列；步骤执行切片（R16）。它编译成计划交给 monarch-core——一个可恢复的阶段队列引擎，支持基于游标的续跑，由 monarch-persistence 做日志持久化。银行树声明了 4 条流水线（现金付款、TA 提交、定投派发、独立退款）。

把它们分清的规则：saga 拥有事务边界；流水线拥有流程顺序。二者不可互换，真源树拒绝含混。
