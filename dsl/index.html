The language · from one rule to state

Describe the rule. Trace the change.

Start with Counter: a guard decides whether a command may proceed, a binding supplies an event’s payload, and a fold turns that event into state. Business declarations live in one author tree; technical bindings and handwritten implementations have separate responsibilities. Neither a graph nor a green gate replaces human agreement on the rule.

01

Counter: one causal chain, three views

1 · Business meaning

Start with count = 0. Request SetCount(id="counter-1", count=2). A nonempty id and a nonnegative count pass both guards. Bind the parameters into CountSet; applying that event sets id to counter-1 and count to 2. A negative count is rejected without an event. This is assignment, not increment.

2 · Current author input

These are reformatted JSON array fragments from the shipped Counter slice at cb860b5c, not a complete YAML file or project. Keep their original positions and the surrounding type declarations. The guide’s public init creates the whole project.

payload.guards — evaluated in order, against command parameters and current state.

[
  {"kind":"invariantRef","ref":"nonempty-id","errCode":"EMPTY_ID","cond":"param.id.nonEmpty","onFail":"reject"},
  {"kind":"invariantRef","ref":"nonnegative-count","errCode":"NEGATIVE_COUNT","cond":"param.count >= 0","onFail":"reject"}
]

events.CountSet.bindings — populate the event, not the state.

[

  {"slot":"count","expr":"param.count"}
]

events.CountSet.foldAssignments — replay reads the recorded event, not the original command.

[
  {"slot":"id","expr":"event.id"},
  {"slot":"count","expr":"event.count"}
]

02

Guard, binding, fold: different jobs

Guard

May this command proceed?

A true predicate proceeds to the next guard. On false, onFail: reject stops with its error code; succeed-empty stops successfully with no events. Neither runs later guards. The policy is not the predicate’s return value.

Binding

What fact is recorded?

Emission bindings fill event slots from declared command/state values, or explicitly admitted, version-pinned host outputs. An event field and a state field are not interchangeable.

Fold

What state follows this fact?

Event application alone evolves aggregate state. A fold replays state + event; it cannot call a host, read the clock/network or depend on the original command parameters.

Simultaneous updates, not a script

Every right-hand side and update base reads the same immutable pre-event snapshot. Compute all results, then form a new state. Removing a map entry in one assignment does not hide its old value from another. Each event may assign each target only once: no ordering trick, last-write-wins or intermediate-state reads.

A fold map read such as state.pending[event.key] produces an optional value in typed products. The receiving type must admit that optional; it is not an unchecked extraction. Even where a legacy tree precheck accepts a spelling, strict typed admission can still reject it.

EXACT VALUES

Long/Int/Integer use canonical signed-64 decimal strings at the product/oracle boundary, never JS Number. Exact money needs declared nominal types, precision, scale and units. There is no implicit currency, rounding or conversion. Wrong units, precision or overflow fail; money-apply is an operator name, not a built-in banking policy. Host clocks and arbitrary Scala are not replay expressions; literal:SYSTEM_NOW is not a clock call in these strict products.

03

A real slice, unedited

From truth/bank-wealth/…/credit-balance/slices/initialize-account.slice.yaml. One command, five guards, one event, folds and provenance. This source excerpt is not a standalone project or a new bank acceptance run.

Business view: identity, conflict, then idempotency

  1. ACCOUNT_ID: the requested resource must equal this aggregate’s id.
  2. ACCOUNT_CURRENCY: currency must be CNY and the amount must carry that same currency.
  3. ACCOUNT_INIT_CONFLICT: before initialization, proceed; afterwards require the same recorded amount. A different amount rejects before the idempotency guard.
  4. ACCOUNT_INIT_ONCE: !state.initialized being false means succeed-empty. A matching retry emits no second event and skips subsequent guards.
  5. ACCOUNT_SEED_NONNEGATIVE: a fresh seed must be >= 0.00. Zero is allowed; this is not the stricter money-positive predicate.

Expanded semantic view — explanation, not author input

After all five guards pass, the three bindings record resource, currency and amount in AccountInitialized. Its fold sets initialized=true and puts the event amount under the event currency in accountBalance, both against the same pre-event snapshot. For a fresh matching account, 0.00 CNY is valid; a matching initialized retry has no event/fold; a conflicting amount is a rejection. This explains the declaration, not an independent execution of banking behavior.

Guards

Rules with teeth

Guards retain their order and their false-predicate outcome: reject rejects, while succeed-empty ends an idempotent retry without another event. “Non-negative balance” is no longer a comment — it compiles into the generated command handler.

Bindings

Where payloads come from

Every event field is either propagated from a parameter or computed — provenance at the field level, which is what read-model lineage (R10/R11) builds on.

Folds

History becomes state

foldAssignments define how the event updates aggregate state — the algebra the generated event applier implements.

Do not mix four grammar layers

  • Guard condition: finite param/state predicates, Boolean operators, comparisons and admitted collection/member operations. Signed-64 literals and finite +/- need decision @3/@4; older profiles differ. No arbitrary calls or Scala closures.
  • Author value: strings such as event.count, literal:true or literal:1. Member paths need the author v2 opt-in. General infix arithmetic is not a fold value string. Nested literal/add/subtract objects recognized by value-product v2 are still refused by current author prechecks.
  • Micro carrier: opt in with system authoring.micro:"truthsrc.micro/v1". JSON strings such as "count := event.count" and "items := @fold[put](key=event.key, value=event.value)" lower to those outer objects. Argument separation is comma + space; quote punctuation/whitespace using an inner JSON string, escaped in the outer JSON. Micro syntax does not widen semantic admission.
  • Typed product IR: closed op/ref/valueType objects, qualified identities and sources. This is compiler output, not a shortcut around author validation. See the unimplemented refinement RFC and three current defects; do not use @fold[set](value=...) as a recommended spelling.

Pinned references: AUTHORING · micro · SCHEMA · author values · PRODUCTS · typed folds/oracles. Historical sections describe broader legacy carriers; these strict profiles are not arbitrary execution permission.

08

Governance: three gates, not style guides

validate — 0 hard findings

author structure and declared-reference checks, not complete typed admission

Unknown kinds, dangling references, an event defined in two places, a slice without its aggregate — all hard findings. Zero is the only acceptable count. Bank tree as of 2026-11-11: 0 hard verified.

roundtrip — byte-identical

tree → canonical → tree must reproduce the author files exactly

This is the anti-formatting-drift gate. If compilation “normalizes” anything, the roundtrip diverges and the gate fails. Bank tree: 157 atoms, byte-identical verified.

compile-products — strict contracts

formal products must satisfy their schemas before use

Ports, saga IR, execution IR: typed, versioned products compiled from the tree with their own validation. Generated code consumes frozen products only.

AGENTS

The editing contract for AI agents is the same three gates plus stewardship rules: every batch ends validate AND roundtrip green; payload text is preserved verbatim; no tool artifacts inside the tree; one event defined in exactly one slice. It ships with the toolchain as AGENTS.md and a query skill pack.
