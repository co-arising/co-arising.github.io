Hands-on · zero to full loop

The guide: run the whole thing

Three levels, each with a green light at the end: L1 the Counter tutorial (Node only, ~10 min), L2 the bank example pipeline (add a JVM, ~30 min), L3 wiring the MCP server into Claude Code so an agent plans an incremental change by querying the graph. If any step fails, the last sub-section tells you where the red lines are.

00

Environment — pick one path, both are first-class

The toolchain needs Node ≥ 22.13.0 (built-in node:sqlite is why). Level 2 additionally needs a JVM (11+) and sbt. Every command below is copy-pasteable.

Path A · native Node

# macOS (Homebrew)
brew install node@22

# or with nvm
nvm install 22
node --version   # must print v22.13.0 or newer

Path B · Docker (if you don’t want to touch your host Node)

docker run --rm -it -v "$PWD":/work -w /work node:22 bash
# you are now on Node 22 inside the container; everything below works unchanged

Level 2 only · JVM + sbt

# macOS
brew install openjdk@11 sbt

# or the Docker variant for JVM work
docker run --rm -it -v "$PWD":/work -w /work sbtscala/scala-sbt:eclipse-temurin-11.0.24_9_1.10.11_2.13.14 bash

Get the toolchain

npm publication is on the ledger (DEF-03) — until then, a source checkout is the canonical install. Zero npm runtime dependencies means the checkout is the whole toolchain.

git clone https://github.com/co-arising/metarch-truthsrc.git

# smoke test — no SQLite touched, no side effects

Tip: alias truthsrc="node $PWD/metarch-truthsrc/bin/truthsrc.js" makes the rest of this page read literally.

02

L1 · Counter tutorial — the whole loop in miniature

One aggregate, one slice, one rule. You will author, generate, query the anchor both directions, verify, change the tree, see staleness, and regenerate. Green lights are printed by the tool — trust them, not your eyes.

Create the project

refuses to touch an existing directory

node ../metarch-truthsrc/bin/truthsrc.js init counter-lab --format human then cd counter-lab. Look inside: truth/example/… is the whole author tree — aggregate.yaml (state + @rule) and one slice.

Plan before you write

nothing is written yet

… generate-project --plan --format human — the plan lists every file it would write. Read it. Generation should never be a surprise.

Generate & inspect freshness

green light: inputs=current · evidence=verified · synchronized=true

… generate-project --format human then … status-project --out . --format human. Open a generated file — every one carries its anchor header.

Ask both directions

the moment the loop closes

… query-project --knowledge SetCount → the exact file and span. Then … query-project --file <that file> --symbol <symbol> → back to the rule. Knowledge and code, joined.

Change the truth, not the code

see staleness, then re-sync

Edit truth/…/aggregate.yaml: change the count default 0 → 2. status-project now reports changed. … generate-project --update --plan shows the diff plan; --update applies it. Run generate again — written: 0. Idempotence is the gate.

Verify & take the picture

green light: verify passed

… verify-project --out . re-proves every anchor against file bytes. … view-project --out . --html counter-map.html exports a single-file map — open it offline.

03

L2 · The bank example at full scale

157 atoms, 3 aggregates, 2 sagas, 4 pipelines — the same six gates, industrial size. From here the green lights are the project’s own acceptance layers.

git clone https://github.com/MadPolaris/bank-wealth-demo.git
cd bank-wealth-demo

# gate 1+2 — validate & roundtrip (one command; roundtrip is part of the gate)
npm run validate            # ✅ 0 hard · roundtrip: 157 atoms byte-identical

# gate 3 — compile & build the graph store (389 nodes / 413 edges)
npm run compile
node ../metarch-truthsrc/bin/truthsrc.js graph --tree truth/bank-wealth --out bank.graph.sqlite

# gate 4 — generate the CQRS project (235 files); the first run also
#          fetches the pinned 0.3.0 engine jars from Maven Central (sha256-verified)
npm run project             # writes generated/current/

# gate 5 — the handwritten zone is already complete in the repo (35 files);
#          it compiles as part of the generated build:
cd generated/current && sbt compile   # ✅ 0 errors, 534 sources
sbt test                             # ✅ 23/23

# gate 6 — prove every anchor (792)
cd ../.. && node ../metarch-truthsrc/bin/truthsrc.js verify-project \
  --project truthsrc.project.json --out generated/current
WHAT YOU JUST PROVED

That a 157-atom description of a bank wealth domain compiles, becomes a queryable graph, generates a compiling, tested Scala codebase whose 792 anchors verify against file bytes — and that you can re-run every step. The boundary you did NOT cross: running the HTTP service end-to-end (ledger DEF-06 DEF-07).

04

L3 · Wire the graph into Claude Code (MCP)

This is the agentic payoff: an agent that plans changes by querying the knowledge graph instead of grepping the repo. The MCP server ships 26 read-oriented tools verified.

Register the server

# from any directory (path to your metarch-truthsrc checkout)
claude mcp add truthsrc -- node /absolute/path/to/metarch-truthsrc/bin/truthsrc.js mcp

Install the query skill

The toolchain ships a skill that teaches an agent the query discipline (budgeted graph walks, following next_actions, over-report semantics of blast_radius). Copy it into your project:

mkdir -p .claude/skills
cp -r /absolute/path/to/metarch-truthsrc/skills/truthsrc .claude/skills/

The exercise: plan an incremental change by blast radius

Give the agent a requirement

in Claude Code, inside bank-wealth-demo

Try: “We need to change what happens when an SIP installment fails. Before proposing anything, query the truth graph for the blast radius of SipInstallmentFailed and report which slices, read models and pipelines are affected.”

Watch the discipline work

describe → expand → blast_radius, following next_actions

The agent should walk propagating edges from the event, enumerate affected guards/read-models/pipelines (dozens of nodes within 3 hops), and only then draft a change proposal against the tree — not against code.

Apply the editing contract

agents draft; gates judge

Any tree edit must end with validate (0 hard) and roundtrip (byte-identical) green, then generate-project --update --plan to see the regeneration diff before applying. That’s stewardship, mechanically enforced.

Also shipped: skills for extracting a tree from an existing codebase, from reachable data, or bootstrapping workshop drafts from a one-line description — skills/ in the toolchain repo.

05

Red lines & recovery

NEVER

Never hand-edit derived artifacts — the compiled canonical, .truthsrc/, ledgers, anchors, or generated files. They are regenerated; your edits are void (and detected). If generated code looks wrong, the fix belongs in the tree — that is the entire point.  ·  Never force past a red gate. validate findings and roundtrip divergence are information, not obstacles.  ·  Graph store? Delete freely — it is a pure cache, rebuild with one graph command.

Stuck? The toolchain README has a diagnostics section; the facts page tells you exactly which claims are verified on which date — if your numbers differ from ours, trust your terminal.
