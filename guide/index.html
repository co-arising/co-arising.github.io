Environment — choose the scope first

The Node-only tutorial and bank source scope need Node ≥ 22.13.0 (node:sqlite) F-13. Compiling generated Scala needs a JVM and sbt. Formal anchors/code/service verification additionally needs explicit matched materials; formal code/service is scoped to native Darwin x64 / JDK11 F-28. Read the prerequisites before treating any command as an acceptance path.

02

L1 · Counter tutorial — the whole loop in miniature

One aggregate, one slice, one rule. You will author, generate, query the anchor both directions, verify, change the tree, see staleness, and regenerate. Green lights are printed by the tool — trust them, not your eyes.

Create the project

refuses to touch an existing directory

node ../metarch-truthsrc/bin/truthsrc.js init counter-lab --format human then cd counter-lab. Look inside: truth/example/… is the whole author tree — aggregate.yaml (state + @rule) and one slice.

Plan before you write

nothing is written yet

… generate-project --plan --format human — the plan lists every file it would write. Read it. Generation should never be a surprise.

Generate & inspect freshness

green light: inputs=current · evidence=verified · synchronized=true

… generate-project --format human then … status-project --out . --format human. Open a generated file — every one carries its anchor header.

Ask both directions

the moment the loop closes

… query-project --knowledge SetCount → the exact file and span. Then … query-project --file <that file> --symbol <symbol> → back to the rule. Knowledge and code, joined.

Change the truth, not the code

see staleness, then re-sync

Edit truth/…/aggregate.yaml: change the count default 0 → 2. status-project now reports changed. … generate-project --update --plan shows the diff plan; --update applies it. Run generate again — written: 0. Idempotence is the gate.

Verify & take the picture

green light: verify passed

… verify-project --out . re-proves every anchor against file bytes. … view-project --out . --html counter-map.html exports a single-file map — open it offline.

L2 · Bank generation and formal workshop scopes

PREREQUISITES — NOT AN INSTALLATION SHORTCUT

Node-only source checks, convenience generation and formal workshop acceptance are different entry points. The convenient npm run project may obtain engines, but formal anchors/code/service requires both an explicit clean1134 archive and an already prepared runtime-supply directory. The matched CLI, complete paired source materials and archive have no confirmed public delivery channel (DEF-15). Do not treat this page as a one-command public reproduction.

Formal scopeRequired inputs and environment
sourceYour bank checkout, the complete adjacent matched tool checkout and Node. No JVM, database or browser. Rejects unused --archive and --runtime-supply flags.
anchorsSource inputs plus --archive: an absolute path to the existing clean1134 archive (frozen compiler/toolchain and third-party dependencies), and --runtime-supply: an absolute path to the existing prepared 0.3.0 receipt.json + maven/ directory, matching the project F-23. Neither is optional.
codeBoth supplies above, plus native Darwin x64, an installed x64 JDK11 selected by --java-home, and the sandbox/Python prerequisites F-28.
serviceAll code prerequisites, plus a new exclusive resource lease, available Docker/socket and pinned database images, and explicit Playwright module and chrome-headless-shell paths. Service scope cannot omit the browser.

Formal verification does not implicitly download, prepare or fall back to P23. The composed supply excludes the archive’s old engines and selects the separately locked runtime supply; the archive is not re-signed. The legacy offline-bundle migration remains separate (DEF-20). See the accepted scope and material contract.

Preflight only — set your own real paths first

Run from your own bank checkout root with its matched adjacent tool checkout. Set BANK to that checkout’s absolute path. For code scope, also set ARCHIVE, RUNTIME_SUPPLY and JAVA_HOME_BANK to existing, absolute local paths described above. These are required variables, not download locations or supplied files.

Source preflight has no archive/runtime flags.

: "${BANK:?Set BANK to your own bank checkout absolute path}"
node "$BANK/tools/bank-workshop.mjs" doctor --through source --format human

Code preflight explicitly selects both supplies and the installed JDK.

: "${BANK:?Set BANK to your own bank checkout absolute path}"
: "${ARCHIVE:?Set ARCHIVE to the existing clean1134 archive absolute path}"
: "${RUNTIME_SUPPLY:?Set RUNTIME_SUPPLY to the prepared 0.3.0 supply directory absolute path}"
: "${JAVA_HOME_BANK:?Set JAVA_HOME_BANK to the installed x64 JDK11 absolute path}"
node "$BANK/tools/bank-workshop.mjs" doctor --through code \
  --archive "$ARCHIVE" --runtime-supply "$RUNTIME_SUPPLY" \
  --java-home "$JAVA_HOME_BANK" --format human

Doctor is preflight, not acceptance. A subsequent verify must create a fresh run in a never-used direct child of the bank’s target/, with an existing parent and a canonical absolute path. Do not reuse an old run. Doctor without --run does not check that parent. Report/view and independent session start/status/stop use the run’s sealed supply; session commands reject archive/runtime-supply overrides. A later fix needs new execution evidence, not a relabelled report.

Convenience generation — not the workshop recipe

The existing local path validates, generates into generated/current/, compiles handwritten production sources with the generated project, and verifies anchors. Its first generation may fetch SHA-256-pinned engines from Maven Central. It does not establish that the formal supplies above are present, and it does not start or accept the service.

04

L3 · Wire the graph into Claude Code (MCP)

This is the agentic payoff: an agent that plans changes by querying the knowledge graph instead of grepping the repo. The MCP server ships 26 read-oriented tools verified.

Register the server

# from any directory (path to your metarch-truthsrc checkout)
claude mcp add truthsrc -- node /absolute/path/to/metarch-truthsrc/bin/truthsrc.js mcp

Install the query skill

The toolchain ships a skill that teaches an agent the query discipline (budgeted graph walks, following next_actions, over-report semantics of blast_radius). Copy it into your project:

mkdir -p .claude/skills
cp -r /absolute/path/to/metarch-truthsrc/skills/truthsrc .claude/skills/

The exercise: plan an incremental change by blast radius

Give the agent a requirement

in Claude Code, inside bank-wealth-demo

Try: “We need to change what happens when an SIP installment fails. Before proposing anything, query the truth graph for the blast radius of SipInstallmentFailed and report which slices, read models and pipelines are affected.”

Watch the discipline work

describe → expand → blast_radius, following next_actions

The agent should walk propagating edges from the event, enumerate affected guards/read-models/pipelines (dozens of nodes within 3 hops), and only then draft a change proposal against the tree — not against code.

Apply the editing contract

agents draft; gates judge

Any tree edit must end with validate (0 hard) and roundtrip (byte-identical) green, then generate-project --update --plan to see the regeneration diff before applying. That’s stewardship, mechanically enforced.

Also shipped: skills for extracting a tree from an existing codebase, from reachable data, or bootstrapping workshop drafts from a one-line description — skills/ in the toolchain repo.

05

Red lines & recovery

NEVER

Never hand-edit derived artifacts — the compiled canonical, .truthsrc/, ledgers, anchors, or generated files. They are regenerated; your edits are void (and detected). If generated code looks wrong, the fix belongs in the tree — that is the entire point.  ·  Never force past a red gate. validate findings and roundtrip divergence are information, not obstacles.  ·  Graph store? Delete freely — it is a pure cache, rebuild with one graph command.

Stuck? The toolchain README has a diagnostics section; the facts page tells you exactly which claims are verified on which date — if your numbers differ from ours, trust your terminal.
