1. Strategic Overview (Level 0): The Macro Terrain Map

To hunt latent bugs systematically inside metarch-truthsrc, discard one misconception first: it is not a "YAML-to-template" scaffolder; it is a five-stage domain compiler built across two historical geological strata.

  • Stratum 1 (v1 Strict-Governance Legacy Layer, emitter/families/): 24 deterministic Scala CQRS/Play emitters locked by golden-file parity in emitter/parity.mjs (value objects, aggregate protocols, Akka persistence, Protobuf converters, Play runtime, and more).
  • Stratum 2 (v2 EARS-Native Trunk, lib/ears/ + lib/v2/): Orthogonal YAML structure loader, EARS 1.0 lexer/parser/binder/Z3 SMT solver, DMN First-Hit witness synthesizer, Canonical Model v2, local SQLite knowledge graph, TS/Scala dual-stack and Scala single-stack generators, locked BDD oracle emitters, mutation testing, and anti-cheat write guards.

Most real-world bugs do not live inside isolated function logic; they live at stratum boundaries and fan-out seams where one semantic concept is independently translated by multiple downstream consumers. Figure 1 maps the six macro stages alongside the four high-risk fault lines:

Two Essential Top-Level Mental Models

  1. Dual-Stack vs. Scala Single-Stack Delivery:
    • typescript gives millisecond zero-compile Node 22 feedback for rapid prototyping and demos; scala-cqrs-play-service-v2 delivers the full production Akka/Play/Protobuf/ScalikeJDBC runtime.
    • Since 0b925ad introduced lib/v2/target-resolution.mjs, Scala production projects no longer carry dual-slot overhead (*.cloze.ts + *Impl.scala): when only generated-scaffold/scala (or .truthsrc/generated-scala-manifest.json) exists without generated-scaffold/ts, tasks-v2, verify-v2, and check-v2 automatically operate in Scala single-stack mode.
  2. The Blind Spot Between Offline scalac and Live sbt stage:
    • To keep TDD loops sub-second/second-level, verify-v2 invokes standalone scalac + ScalaTest while filtering out Akka/Play/ScalaPB/ScalikeJDBC framework files.
    • Therefore green offline verify-v2 does NOT guarantee green sbt -batch stage or HTTP 200 on Play. Play controllers, ReadSide JDBC repositories, Protobuf converters, Guice DI modules, and conf/routes are only truly verified by a real sbt -batch stage and live Play 2.8.18 HTTP roadshow.

4. Underground Tunnels Map (Level 3): 14 Hidden Cross-File Couplings

On the surface the compiler pipeline looks clean and modular. What actually breaks multi-subdomain production projects (such as a 6-subdomain exam platform with 50 domain behaviors and 23 @cloze slots) are 14 underground tunnels (T01–T14)—pairs of modules that never directly call each other yet silently share fragile invariants:

Network A · Type & Nominal System Faults (T01–T03)

  1. T01 · 6-Way resolvedType.kind === 'record' Re-Translation:
    • structure-loader.mjs normalizes both ExactType (such as Money) and ValueObject into { kind: 'record', typeName }.
    • At least six downstream files each maintain their own buildNominalIndex / scalaTypeOf / defaultScalaExpr: v1-strict-scala.mjs, v1-strict-block-cd.mjs, v1-strict-readside.mjs, v1-strict-policy.mjs, v1-strict-api-auth.mjs, and witness-materialize.mjs.
    • Failure mechanism: Missing case 'record' in any single consumer silently degrades types to String—directly causing Play ReadSide String assigned to BigDecimal/Long (Issue #2) and ReadModel nominal-field compile errors (Bug #4).
  2. T02 · SPEC-S10 Idiomatic Primitive Json.toJson vs. Nominal Codecs:
    • In v1-strict-readside.mjs, primitive sequences like Vector[String] must keep Json.stringify(Json.toJson(row.topics)) and .as[Vector[String]] (pinned by SPEC-S10), while collections/maps containing ExactType or ValueObject must branch via typeUsesNominal into recursive jsEncodeExpr / jsDecodeExpr.
  3. T03 · Four-Way Implicit Assumption That aliases Includes 'state':
    • If YAML defines custom aliases: [bal] without 'state', v1-strict-scala.mjs and witness-materialize.mjs misread state.field as a nested record member and emit state.copy(state = state.state.copy(...)) (Bug #7). Every consumer must normalize aggregate aliases to include 'state'.

Network B · 1.0/2.0 Bridge & Offline scalac Faults (T04–T07)

  1. T04 · Duplicated SBT_FRAMEWORK_IMPORT_RE Offline scalac Filter:
    • verify-gate.mjs:359 and mutation-gate.mjs:210 each hold a copy of the framework import regex that strips Akka/Play/ScalaPB/ScalikeJDBC/converter files out of standalone scalac.
    • Rule of thumb: Any generated Scala file referencing a filtered trait (such as zero-VO DomainConverters.scala extending <Agg>ProtoConverters) MUST carry a matching framework import—otherwise sbt stage succeeds while offline verify-v2 fails with not found: type. Always update both copies together.
  2. T05 · 1.0 emitter/families/ 24-Family Parity Red Line:
    • emitter/parity.mjs pins golden bytes and runNegatives assertions across all 24 families (for instance, proto-converter.mjs requires valueObjects.length > 0).
    • Rule of thumb: Handle v2 edge cases (like zero-VO projects) in v1-strict-block-cd.mjs rather than weakening 1.0 negative batteries.
  3. T06 · Hybrid L1+L2 Aggregate RuleParams & SPEC-S4 Zero-Noop Contract:
    • Aggregates mixing L1 deterministic rules and L2 @cloze rules must unify all params under <Agg>RuleParams (never splitting out <Agg>DomainServiceRuleParams).
    • Because SPEC-S4 forbids exposing val Noop on non-empty <Agg>Computations in production code, scala-strict-scalatest.mjs passes null.asInstanceOf[<Agg>Computations] for L1 rule tests on hybrid aggregates.
  4. T07 · tools/lint.mjs Architecture Guard:
    • tools/lint.mjs scans all 626 JS/MJS files: zero domain/business identifiers in generic core, zero net.imadz literals outside lib/runtime-profile.mjs, and zero hardcoded 'app/' paths inside active emitter/families/.

Network C · Witness Materialization & Oracle Faults (T08–T10)

  1. T08 · Sparse Z3 Witness → witness-materialize Semantic Distortion:
    • first-hit-witness.mjs probes Z3 only for guard-referenced symbols; witness-materialize.mjs fills the rest.
    • Two classic traps: (1) Overwriting [] with synthetic non-empty lists on rejected rules destroys len(items) == 0 witnesses (Bug #1); (2) Omitting bindPrincipal, server stateSnapshot, or sending scalars to sequence fields breaks entire application test suites (Issue #3).
  2. T09 · Dual Event-Field Resolution:
    • Event fields can be explicitly declared or derived from command parameters/lineage. Both v1-strict-scala.mjs and [POSTCOND] emitters in scala-strict-scalatest.mjs must share resolveCanonicalEventFields(agg, ev) or case-class arities drift apart (Bug #6).
  3. T10 · 4-Way 5-Layer Authz PEP/PDP Mirroring: - onion-ts.mjs, onion-scala.mjs, v1-strict-api-auth.mjs (Play controllers), and interfaces-http.mjs (HTTP oracles) must stay byte-for-byte semantically aligned on: skipping public routes for 401/403 checks, injecting allow-PDP for both external-pdp and resource-policy, appending query params for GET routes, mapping errors via HttpStatusMapper.statusForRejection, converting JsNull => null, parsing X-Entitlements / X-Principal-Attr-*, and enforcing ownerField / requiresEntitlement / rowScope + ServerSnapshotProvider.load.

Network D · Monolith Packaging, Targets & Gate Faults (T11–T14)

  1. T11 · Silent dedupBy Swallowing in mergeCanonicalsForBc & Stale Files: - Look at generators/scala-cqrs-play-service-v2/generate.mjs:135: multi-subdomain monolith merges deduplicate valueObjects, exactTypes, readModels, aggregates, ports, and stories by short x.name. Two subdomains defining same-named types with different fields silently drop the second definition. Meanwhile incremental regeneration does not garbage-collect stale .scala files left under old package paths (Issue #4).
  2. T12 · target-resolution.mjs Single-Stack Detection & init-v2 Import Rules: - lib/v2/target-resolution.mjs unifies target resolution across tasks-v2, verify-gate, check-v2, and cli.mjs; init-v2.mjs must correspondingly switch forbiddenImports for Scala-only repos so Play controller imports are never false-flagged.
  3. T13 · verify-gate Short-Circuiting Mutation & Open HTTP Server Handles: - Any single failure in the base test suite causes verify-gate.mjs to skip the built-in mutation-gate, deferring mutation timeouts or surviving-mutant surprises until after the entire suite turns green. Additionally, unclosed HTTP listeners in interfaces-http can keep standalone node --test workers alive after reporting counts.
  4. T14 · Cross-Version DI Signature Drift in overwrite: false Handwritten Files: - Preserving HandwrittenBindingsModule.scala, ServerSnapshotProviderImpl.scala, and @cloze *Impl.scala files is a strict guarantee—which means when a newer generator adds a constructor dependency (like ServerSnapshotProvider), clean directories pass while pre-existing repos fail to compile until their handwritten bindings are upgraded.
